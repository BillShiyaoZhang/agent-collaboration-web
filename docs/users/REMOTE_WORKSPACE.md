# 连接 Ambient 本地工作区

这项入口连接你自己电脑上的 Ambient。需要先登录云账户取得本机接入码，再在本机创建申请、由同一云账户领取，最后回到本机确认。本文描述 main 的实现；线上启用状态和版本以部署仓库的发布及验收记录、实际入口为准。

1. 用你打算授权的账户登录 Agent Comm，打开“本地工作区”或 `/connect-workspace`，点击“生成本机接入码”。复制页面显示的入口地址和接入码；接入码 5 分钟有效且只能用一次，请只粘贴到自己的 Ambient。
2. 在 Ambient 本机的“远程连接”输入入口地址及接入码，再创建连接申请，核对工作区名称、范围和期限。
3. 打开 Ambient 返回的连接链接，或在网页输入本机生成的连接码，点击“以当前账户领取”。接入码与连接码是两个不同步骤，只能由生成接入码的同一账户领取。
4. 页面显示“等待本机确认”。回到电脑上的 Ambient，核对显示的领取账户、权限和到期时间后确认。
5. 保持 Ambient 运行并联网；云端显示“在线”后点击“打开工作区”。网页读取和操作仍在这台电脑上处理。

“操作工作区与运行任务”允许工作区读写和 Agent 执行；“管理模型、Agent 与能力配置”额外允许配置管理。普通 Hermes 聊天配对不包含这些工作区权限。网页领取不会扩大你在本机选择的范围，也不能代替本机确认。

接入码到期后页面会隐藏它；刷新页面不会恢复接入码、自动生成或连接。发码结果未确认时请稍后明确重试；Ambient 创建申请结果未确认时先在本机核实，避免重复接入。生成码和云端领取都不代表已授权远程操作。

列表分为“当前连接”和“已撤销与到期”。历史按页读取，点击“加载更多连接”继续；多页期间不自动重排，点击“重新读取”回到最新一页。浏览器最多保留最近载入的 500 项，继续加载仍能查看更早记录。

“离线”时请检查电脑、Ambient 和网络。页面不会重新提交已有任务；重连后由 Ambient 原有持久状态恢复。授权到期后需在本机重新发起连接。

可以在云端或本机撤销。撤销停止后续访问并关闭已经打开的远程连接，不删除本机工作区或回滚已经执行的任务。删除云账户前会先停止该账户的所有工作区访问；若入口暂时不可达、撤销尚未确认，账户删除会停止并要求稍后重试。云端撤销已完成但本次数据库删除失败时，账户可能仍在，工作区访问已经停止。

工作区内容和模型密钥保留在本机。中转 Gateway 处理网页 HTTP/WS 数据且能够看到传输正文，但不保存正文副本；运营者需正确部署 TLS、日志、配额及存储策略。原有 Hermes 账户聊天副本继续遵循其原来的权限和保存规则。

实现与部署说明见 [云入口契约](../architecture/REMOTE_WORKSPACE.md)。

若运营者提供临时子域入口，请使用支持当前安全特性的现代浏览器。入口切换后需要重新登录，原账户和本机工作区保留；原生客户端可能暂不可用。从工作区点击返回同站门户的链接可能被拒绝，此时在地址栏输入门户地址或使用书签打开。正式入口应使用运营者提供的地址，不要把工作区网址改成门户下的路径。临时入口仍需 HTTPS，也需要同样的领取、本机确认及撤销流程。
